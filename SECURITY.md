# Security reporting — MyDms (MIT)

MyDms is an early open-source foundation. **No production deployment is claimed or supported by the current S6-0 evidence.**

Please do not publish exploits with actual credentials, customer information, financial records or sensitive environment details in public Issues or Pull Requests. Use a private channel agreed with repository maintainers, or GitHub private vulnerability reporting **if and when enabled** by the repository administrator. Do not assume that private reporting is configured.

A security report should ideally describe the affected source commit/version, reproducible nonproduction scenario, expected/actual outcome, impact and suggested mitigation without including live tenant data.

Repository maintainers should triage reports, validate on isolated synthetic fixtures, limit public detail until a fix is available and maintain affected source SHA/CI evidence. This policy does not waive Product C′ safety gates or permit testing against production tenants/providers.
